# NixOS configuration

My personal NixOS setup, as a flake. One host (`tuxedo`), a handful of
shared modules, no home-manager — everything lives at the system level.

## Layout

```
flake.nix                 inputs + nixosConfigurations
hosts/
  tuxedo/
    default.nix           host: hostname, bootloader, graphics quirks, imports
    hardware-configuration.nix   generated by nixos-generate-config
modules/
  core.nix                nix daemon, gc, networking, locale, shell, power
  hardware.nix            bluetooth, pipewire, upower, acpilight, keyd
  desktop.nix             hyprland/niri, sddm, fonts, theming, ydotool, session vars
  packages.nix            system profile packages
  services.nix            user units: wallpaper daemon, desktop shell
  users.nix               user accounts
```

## Hosts

| Host     | Hardware                          | Boot          | Root |
| -------- | --------------------------------- | ------------- | ---- |
| `tuxedo` | Intel + RTX 4050 laptop (x86_64)  | systemd-boot  | ext4 |

The discrete GPU is deliberately disabled — see [Notes](#notes).

## Usage

Rebuild and switch:

```sh
sudo nixos-rebuild switch --flake .#tuxedo
```

Build without activating (useful for checking a change compiles):

```sh
nixos-rebuild build --flake .#tuxedo
```

Test until reboot, or stage for the next boot:

```sh
sudo nixos-rebuild test --flake .#tuxedo
sudo nixos-rebuild boot --flake .#tuxedo
```

Update all flake inputs (or just one):

```sh
nix flake update
nix flake update nixpkgs
```

## Generations

Old generations are collected automatically: `nix.gc` runs weekly and drops
anything older than two days, and systemd-boot keeps at most ten entries in
the menu.

That covers the *system* profile only. The user profile is a separate root
and has to be collected as your own user:

```sh
nix-collect-garbage --delete-older-than 2d
```

## Flake inputs

- **nixpkgs** — `nixos-unstable`
- **[apple-fonts](https://github.com/Lyndeno/apple-fonts.nix)** — San Francisco fonts
- **[aven](https://github.com/raine/aven)** — local-first TUI task manager
- **[awww](https://codeberg.org/LGFae/awww)** — Wayland wallpaper daemon
- **[workmux](https://github.com/raine/workmux)** — git worktree + tmux workflow tool

All four follow the same `nixpkgs` as the system.

## What's configured

- **Desktop:** Hyprland (with UWSM, the default session) and Niri, both on
  Wayland, behind SDDM themed with `sddm-astronaut` (`pixel_sakura`).
- **Shell UI:** `kuori`, a quickshell desktop shell, run as a user unit. It
  also acts as the session's polkit agent.
- **Wallpaper:** `awww-daemon` as a user unit, restoring its last wallpaper
  on start.
- **Fonts/icons:** Nerd Fonts plus SF Pro as the default sans, Manrope and
  Material Symbols; MoreWaita icons for both GTK and Qt (Qt follows GTK via
  the `gtk3` platform theme); Bibata Modern Ice cursors, set through
  `XCURSOR_THEME` so Hyprland stops drawing its built-in one.
- **Locale:** `en_US.UTF-8` with Finnish regional formats, `fi` console and
  X11 keymap (`nodeadkeys`), `Europe/Helsinki`.
- **Audio/input:** PipeWire (ALSA + Pulse), Bluetooth with battery reporting,
  and keyd mapping Caps Lock to Ctrl on hold / Esc on tap.
- **Power:** power-profiles-daemon, acpilight for backlight, and PCI runtime
  power management for the unused discrete GPU.
- **Clipboard/screenshots:** wl-clipboard with cliphist, grim/slurp/grimblast.
- **Shell:** fish, with NixOS' default shell aliases cleared.
- **Unfree packages** are allowed.

## Adding a host

1. Run `nixos-generate-config --show-hardware-config > hosts/<name>/hardware-configuration.nix`
   on the target machine.
2. Add `hosts/<name>/default.nix` importing the hardware config and the
   modules you want, and set `networking.hostName`.
3. Register it under `nixosConfigurations` in `flake.nix`.

Note that `hosts/tuxedo/default.nix` carries machine-specific graphics
workarounds that should not be copied blindly to another host.

## Notes

**`system.stateVersion`** is pinned to the release the machine was installed
with and should not be bumped on upgrade.

**The discrete GPU is disabled.** `nouveau` is blacklisted on `tuxedo`.
SDDM's weston greeter takes the first DRM card it finds, and when nouveau
enumerates ahead of i915 that is the RTX 4050 — which cannot do atomic
modesetting under nouveau, so the greeter dies and the machine boots to no
graphical session at all. Card numbering shifts between kernels, so this is
latent rather than reliably reproducible. Blacklisting the module also takes
the card out of runtime power management (an unbound PCI device defaults to
`power/control=on`), hence the paired udev rule putting it back on `auto` so
it can still reach D3cold. To actually use the card, remove both and set up
`hardware.nvidia` with PRIME offload.

**The desktop shell runs from a working copy.** The `kuori` user unit starts
quickshell against `~/.config/kuori`, a path outside this
repo, because the shell is developed in place. The unit fails if that
checkout is missing — and since the shell is also the polkit agent, that
means no authentication prompts in the session either.

**Input synthesis is off by default.** `ydotoold` is dropped from
`multi-user.target`, so anything using ydotool needs an explicit
`systemctl start ydotoold` first. Each start prompts for a password and the
approval is not cached, on purpose: whatever can reach the daemon's socket
can type into the focused window, including a terminal holding a cached sudo
timestamp.
